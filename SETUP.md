# Vibe Compilers - Setup Guide

This guide provides information about the directory structure and setup process for the Vibe Compilers repository.

## Directory Structure

The repository is organized into the following main directories:

### Root Structure

```
vibe_compilers/
├── abacus/          # Educational vibe compiler for beginners and children
├── buddy/           # Coding buddy/persona creation tools
├── migraine/        # Migration and refactoring guidance system
├── yaska/           # Emotionally intelligent persona builder
├── .gitignore       # Git ignore patterns
├── README.md        # Main repository documentation
└── SETUP.md         # This file
```

### abacus/

The **Abacus** vibe compiler helps beginners (especially children ages 7-14) bridge the gap between problem-solving and coding.

**Files:**
- `abacus.vc` - Main Abacus vibe compiler
- `*.jmp` - Modular prompt extensions (educational, debugging, decomposition, etc.)
- Various compiler modules (ReactCompiler, WebsiteBuilderCompiler, pygameCompiler, etc.)

**Dynamic Directories:**
- `blueprints/` - Created automatically when using Abacus to store `.abc` files (not tracked in git)

### buddy/

The **Buddy** system provides tools for creating coding buddy personas.

**Files:**
- `buddy_creator.jmp` - Prompt module for buddy creation
- `buddy_creator.js` - Interactive JavaScript tool

### migraine/

**MIGRAINE** (Migration Guidance & Refactor Assistant with Intentional, Guided Navigation & Execution) helps experienced developers with high-stakes migrations and refactors.

**Files:**
- `migraine.vc` - Main MIGRAINE vibe compiler
- `README.md` - MIGRAINE-specific documentation
- `00_project_mayhem.jmp` through `10_cleanup.jmp` - Sequential prompt modules for the migration process

**Subdirectories:**
- `project_mayhem/` - Storage for user-provided legacy artifacts and context files
- `the_burrow/` - MIGRAINE-generated structured outputs
  - `architecture/` - System design diagrams and architectural decisions
  - `authentication/` - Authentication flow documentation
  - `tdd_plan/` - Test coverage planning
  - `misc/` - Other generated outputs

**Generated Files** (created during MIGRAINE usage):
- `stdout_thoughts.mig` - Stream-of-consciousness logs
- `project_mayhem/SOAP.mig` - Structured Overview of Artifact Provenance
- `the_burrow/architecture/atlas.mig` - Mermaid diagram of system design
- `the_burrow/architecture/decisions.mig` - Architectural reasoning notes
- `the_burrow/authentication/auth_flows.mig` - Permission and login transitions
- `the_burrow/tdd_plan/coverage_matrix.mig` - Test coverage strategy
- `the_burrow/execution_plan.mig` - Refactor execution TODO list
- `the_burrow/misc/other_outputs.mig` - Catch-all for miscellaneous outputs

### yaska/

**Yaska** is a vibe compiler focused on building emotionally intelligent coding personas that feel like supportive friends.

**Files:**
- `yaska.vc` - Main Yaska vibe compiler
- `yaska_generalized.vc` - Generalized version of Yaska

## File Extensions

- `.vc` - Vibe Compiler files (main compiler definitions)
- `.jmp` - "Just More Prompt" files (modular prompt extensions)
- `.abc` - Abacus Blueprint Component files (generated by Abacus, stored in blueprints/)
- `.mig` - Migration files (generated by MIGRAINE, stored in migraine/)

## Setup Instructions

### Prerequisites

No special installation is required. The vibe compilers are markdown-based prompt files designed to be used with AI systems.

### Getting Started

1. **Clone the repository:**
   ```bash
   git clone https://github.com/InvaderSquibs/vibe_compilers.git
   cd vibe_compilers
   ```

2. **Choose a vibe compiler:**
   - For educational purposes or beginners: Use `abacus/abacus.vc`
   - For creating coding personas: Use `yaska/yaska.vc` or `buddy/buddy_creator.jmp`
   - For migrations and refactoring: Use `migraine/migraine.vc`

3. **Pull into context:**
   Reference the appropriate `.vc` or `.jmp` file in your AI conversation to activate the compiler behavior.

### Using MIGRAINE

When using MIGRAINE, the system will automatically create files in the `migraine/` subdirectories as needed. The directory structure is pre-created and ready to receive generated content.

### Using Abacus

When using Abacus, a `blueprints/` directory will be created automatically in your working directory to store `.abc` files. This directory is not tracked in the repository.

## Cross-Platform Compatibility

This repository is fully compatible with:
- **Linux** - All file paths use forward slashes
- **macOS** - Native compatibility with Unix-style paths
- **Windows** - Works with Git for Windows and modern Windows 10/11 (which supports forward slashes)

### Windows-Specific Notes

- Use Git Bash, PowerShell, or Windows Terminal for best experience
- File paths in the documentation use forward slashes (/) which work in modern Windows
- If using older Windows tools, replace forward slashes with backslashes (\) where needed

## Contributing

5. Update the main README.md if adding a new compiler category
